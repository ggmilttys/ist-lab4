## Шаг 2. Изучение структуры и формулирование аналитических вопросов

### 2.1. Назначение таблиц

| Таблица | Назначение |
|---|---|
| `groups` | Учебные группы |
| `students` | Студенты |
| `teachers` | Преподаватели |
| `courses` | Учебные курсы |
| `enrollments` | Записи студентов на курсы |
| `results` | Итоговые оценки завершённых записей |

### 2.2. Первичные и внешние ключи

Таблица `enrollments` связывает студентов и курсы. Поле `student_id` указывает на студента, а `course_id` — на курс. Один студент может записаться на несколько курсов, и на одном курсе могут обучаться несколько студентов. Поэтому связь между студентами и курсами является связью «многие ко многим», реализованной через `enrollments`.

Таблица `results` связана с `enrollments` через `enrollment_id`. Для одной записи на курс может существовать один итоговый результат или не быть результата. В учебной базе у `results.enrollment_id` обеспечивается уникальность.

### Разница между WHERE и HAVING

`WHERE` фильтрует отдельные строки до группировки. `HAVING` фильтрует уже сформированные группы после `GROUP BY`, поэтому с его помощью можно задавать условия для агрегатных функций, например `COUNT(*)`.

### Разница между INNER JOIN и LEFT JOIN

`INNER JOIN` возвращает только записи, для которых есть совпадения в обеих таблицах. `LEFT JOIN` возвращает все записи из левой таблицы и соответствующие им записи из правой. Если совпадения нет, значения правой таблицы будут `NULL`.

## Шаг 7. Индивидуальное исследование

### Вариант 3

**Вопрос:** На каких курсах больше всего оценок ниже 70 баллов? Укажите абсолютное количество и долю.

### 7.1. Используемые таблицы и показатели

Для анализа используются:

- `courses` — название курса;
- `enrollments` — связь курса с записью студента;
- `results` — итоговая оценка.

Таблицы соединяются по ключам `courses.id = enrollments.course_id` и `enrollments.id = results.enrollment_id`.

Рассчитываются:
- общее количество оценок по курсу;
- количество оценок ниже 70 баллов;
- доля оценок ниже 70 баллов от общего количества оценок курса.

### 7.2. Основной аналитический запрос

```sql
SELECT
    c.course_name AS course,
    COUNT(r.id) AS total_scores,
    SUM(CASE WHEN r.score < 70 THEN 1 ELSE 0 END) AS below_70,
    ROUND(
        100.0 * SUM(CASE WHEN r.score < 70 THEN 1 ELSE 0 END)
        / COUNT(r.id), 2
    ) AS below_70_percent
FROM courses AS c
INNER JOIN enrollments AS e ON e.course_id = c.id
INNER JOIN results AS r ON r.enrollment_id = e.id
GROUP BY c.id, c.course_name
ORDER BY below_70 DESC, below_70_percent DESC;
```

Результат: наибольшее количество оценок ниже 70 баллов обнаружено на курсе «Разработка API» — 16 из 31 оценки, что составляет 51,61%. На втором месте — «Визуализация данных»: 15 из 31 оценки, или 48,39%.

![](./images/step71.png)

### 7.3. Проверочный запрос

Цель: проверить общее количество оценок и количество оценок ниже 70 баллов во всей таблице `results`.

```sql
SELECT
    COUNT(*) AS total_scores,
    SUM(CASE WHEN score < 70 THEN 1 ELSE 0 END) AS scores_below_70,
    ROUND(
        100.0 * SUM(CASE WHEN score < 70 THEN 1 ELSE 0 END)
        / COUNT(*), 2
    ) AS overall_percent
FROM results;
```

Результат: всего в таблице 850 оценок, из них 236 ниже 70 баллов. Их общая доля составляет 27,76%. Этот запрос проверяет общий подсчёт, но не заменяет группировку по курсам в основном запросе.

![](./images/step72.png)

### 7.5. Выводы

1. Наибольшее абсолютное количество оценок ниже 70 баллов обнаружено на курсе «Разработка API» — 16 оценок.
2. Доля оценок ниже 70 баллов на курсе «Разработка API» составляет 51,61%, то есть больше половины всех оценок этого курса.
3. На втором месте находится курс «Визуализация данных» — 15 оценок ниже 70 баллов, или 48,39%.

### 7.6. Ограничение анализа

В расчёт включены только записи, для которых существует итоговая оценка в таблице `results`. Активные и отменённые записи без итоговой оценки не учитываются. Кроме того, доля низких оценок показывает частоту таких результатов, но сама по себе не объясняет причины низкой успеваемости.
